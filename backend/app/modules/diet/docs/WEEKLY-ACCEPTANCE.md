## 保护边界与已知限制

两个工作树各 121 个受保护文件的 Git 归一化内容与 HEAD 一致；其他成员业务、公共认证、数据库配置、公共导航、client.js、001～004 和来源包不变。仅公共库文件存在精确 .gitignore 例外，私人数据库及虚拟环境继续忽略。

当前仍是本机共享 profile_id=1；账号角色控制访问，不是多用户档案隔离。周计划页面及 API 明确显示这一边界。自由文本必须人工确认映射，未知成分遇到硬禁忌会保守排除，可能没有候选；系统不会为保证 21 道不同菜谱而虚构内容或削弱过滤。无目标时不生成默认热量，通用健康目标仅作背景依据。

既有已反馈/历史项目不可自动覆盖。所选共享目标被删除、份数或餐次比例需要改变时创建新计划，旧计划及版本保留。正式库部署、多档案设计、成分与过敏安全补充审核仍需相应负责人协调和单独授权。
